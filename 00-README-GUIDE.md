## How to use

For each project, copy the corresponding `README.md` into the root of that GitHub repository and replace the existing README if appropriate.

Before publishing:

- Add verified metrics where `[add value]` appears.
- Add real screenshots/architecture diagrams where indicated.
- Check that the technology list matches the final code.
- Add the repository's actual run instructions.
- Add a demo link if one exists.
- Do not add fabricated accuracy, benchmark, dataset, or deployment claims.

## Recommended final README structure

Each project should answer:

**What is it? → Why did I build it? → How does it work? → What did I learn? → What are the results? → What are the limitations? → What would I improve next?**

This makes the GitHub repositories read like engineering/research projects rather than assignment dumps.
